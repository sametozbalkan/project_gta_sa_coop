Goal: play the GTA San Andreas story in 2-player co-op with a friend, on a private build of CoopAndreas (GPL-3.0).

Repository: github.com/sametozbalkan/project_gta_sa_coop (public), branch `main`. The user allowed the architect to commit and push there (2026-10-15). Local only (git-ignored): `.tools/`, `backups/`, `dist/`, build outputs.

Group 1 delivery: the user had Codex prepare it on branch `codex/group1-delivery` (2026-10-15, with `gpt-6.1-sol` agents); this architect session and the Opus agents carried it on, and on 2026-10-16 the user had the branch fast-forwarded into `main`. Work continues on `main` under the Working model below. Two-player acceptance follows `docs/test-grup-1.md` (round 1 on 0.3.102: #1–#6 passed, #7 failed and is fixed in 0.3.103). Do not start Group 2 before the user's test approval. At the user's request (2026-10-16) the 0.1.0 work of `docs/design/README.md` started before that test: deploy nothing to the game copy until the user has finished the 0.3.103 test; fixes for 0.3.103 come from tag `v0.3.103-alpha`.

## Layout
- `CoopAndreas/` — CoopAndreas (github.com/Tornamic/CoopAndreas) imported with a `git subtree --squash` style commit at upstream `cec2a7d`; our changes are ordinary commits on top (see Fork changes). Update from upstream with `git subtree pull --prefix=CoopAndreas https://github.com/Tornamic/CoopAndreas.git main --squash`. plugin-sdk is vendored in `CoopAndreas/third_party/plugin-sdk`. Build output: `CoopAndreas/build/windows/x86/<mode>/` (git-ignored).
- `.tools/` (local only) — `xmake/` (xmake 3.1.1, portable); `SannyBuilder4/` (Sanny Builder 4.2.0 with the `sa_sbl_coopandreas` mode copied in from `CoopAndreas/sdk/Sanny Builder 4/`); `xdelta3/` (official xdelta3 3.1.0 x86_64, same SHA-256 as the one gtasa-open-downgrader bundles); `patches/Patches_v2.zip` (our verified copy of the downgrade patches, SHA-256 `f7df4272…265b`, pinned in Kur.ps1; `Kur.bat -PatchesZip <path>` or putting it next to Kur.ps1 skips the download); `gta-reversed/` (shallow clone of github.com/gta-reversed/gta-reversed, read-only reference for 1.0 US functions and addresses); `reva/` (the ReVa extension), `ghidra-projects/` (the analyzed gta_sa.exe project with its names TSV and report) and `ghidra-settings/` (this project's own Ghidra settings folder) belong to ReVa (see Reverse engineering).
- `scripts/build.ps1` — builds client, server, proxy and launcher (`-Mode debug` for a debug build). Uses VS 2026 / MSVC x86. From a linked git worktree it uses the main checkout's `.tools`.
- `scripts/deploy.ps1` — installs the build into the game copy and creates the `CoopAndreas` / `CoopAndreas Server` shortcuts there; refuses unless `gta_sa.exe` is 1.0 US. When the game copy's `server\server-config.ini` has no `story-host` key, it adds `story-host = <nickname>` with the nickname from this PC's `coopandreas.ini` (Documents\GTA San Andreas User Files) in the form the server compares. Supports `-WhatIf`.
- `scripts/publish-tunnel.ps1` — publishes CoopTunnel (`dotnet publish` from `tunnel/`: Release, win-x64, self-contained single exe, compressed, no PDB) into `dist/CoopTunnel` (cleared first), copies `tunnel/package/*` next to it (`.bat` with CRLF, `.txt` as UTF-8 with BOM and CRLF) and writes `dist/CoopTunnel.zip`. Takes ~10 s.
- `scripts/package.ps1` — assembles `dist/CoopAndreas-Kurulum/` + `.zip` (~34 MB) from the current build, `dist/CoopTunnel`, `.tools/xdelta3` and a GPL source folder (`KAYNAK/`: `coopandreas-ozel.patch`, the diff from the latest subtree squash commit (`git-subtree-dir: CoopAndreas`) to `HEAD:CoopAndreas`; `OKU.txt` naming its `git-subtree-split` upstream commit and this repository; the tunnel source). Refuses while packaged source directories (`CoopAndreas/`, `tunnel/`, `installer/`, `scripts/`, `docs/`) have uncommitted changes. `-IncludePatches` also puts `.tools/patches/Patches_v2.zip` next to `Kur.ps1` after checking the SHA-256 pinned there (+~880 MB), so a new install doesn't need the patch server. From a linked git worktree it uses the main checkout's `.tools`. Run it after `build.ps1` and `publish-tunnel.ps1` for every build the friend should get, and run both from pwsh 7: `Compress-Archive` in Windows PowerShell 5.1 writes `\` into zip entry names. Any `.ps1` with Turkish text needs a UTF-8 BOM (the ANSI code page here is 1254).
- `tunnel/` — CoopTunnel (C#, .NET 10, Facepunch.Steamworks 2.3.3): carries CoopAndreas' UDP 6767 over Steam P2P with AppID 480 (Spacewar), because the user's line is behind CGNAT. Modes: `host` (next to server.exe, forwards each Steam friend to 127.0.0.1:6767 through its own UDP socket, rejects non-friends unless `--allow-all`), `join` (listens on 127.0.0.1:6767 for the game), `test` (20 pings + route details). Messages carry a 1-byte tag: 0 game, 1 ping, 2 pong, 3 hello. Facepunch 2.3.3 reads the remote identity of a connection as `ip:::` with the current Steam client, so the joiner sends its SteamID64 in a hello and the host checks the friendship from that (unverified peers get no server traffic and are closed after 10 s). `timeBeginPeriod(1)` keeps the 1 ms pump loops from sleeping 15.6 ms. Steam refuses a connection to your own account, so end-to-end tests need two accounts; the first two-account test (2026-10-15) passed: 20/20 pings, Steam ping 13 ms, 0% loss, with ~90 ms spikes from the host's Wi-Fi. `tunnel/package/` holds the `.bat` launchers and `KULLANIM.txt` that go next to the published exe.
- `installer/` — the friend's installer source (`Kur.ps1` for Windows PowerShell 5.1, `Kur.bat`, `OKU-BENI.txt`). It finds the Steam GTA SA, copies it to `C:\Games\GTASA_Coop`, verifies `Patches_v2.zip` by a pinned SHA-256 (downloads it if not next to the installer), applies it with `tools\xdelta3.exe` checking every MD5, then installs the mod, CoopTunnel, a pre-filled `coopandreas.ini` (Steam name, 127.0.0.1:6767; only if missing) and shortcuts (desktop: game and tunnel; game folder: `CoopAndreas`, `CoopAndreas Server` and `CoopAndreas (tani)` with `--coop --coopdiag` for diagnostic logs). Re-running it on an existing 1.0 US folder only refreshes the mod files. Tested end to end on 2026-10-15: 50 s, 422 files identical to the working install.
- `tools/` — Python debugging helpers from the first session, run with `python -I`: `sample_main_thread.py <pid> <plugin-sdk game_sa dir>` (where a hung game's main thread is, symbolized from plugin-sdk addresses), `scm_at_ip.py <main.scm> <crash log>` (which script read a bogus opcode), `pe_peek.py <exe> <va…>` (bytes at virtual addresses, e.g. plugin-sdk version signatures), `audit_hooks.py <exe> <client/src>` (RedirectCall/Nop sites that aren't calls in a given exe), `upnp_external_ip.py`, `apply_downgrade.py`, `safe_unzip.py`. `tools/ghidra/` holds the ReVa wrapper and the Ghidra names pipeline (see Reverse engineering).
- `README.md` (English) and `README.tr.md` (Turkish) — the public project page: what it is, per-region mission progress, features, roadmap, building, limitations, legal note, license and credits. Keep both in step; CoopAndreas is named once (the credit line). Working title until the project is named; the Buy Me a Coffee badge waits for the account.
- `YAPILACAKLAR.md` — backlog and work plan (Turkish, for the user).
- `docs/design/` — designs for the mission mirror layer and the world-state registry (not implemented yet); `README.md` there has the decisions, how the two fit together and the package order (next package 0.1.0-alpha). Implementation starts after the user approves the group 1 test.
- Group 1 packaging: `pwsh -File scripts/package.ps1 -TestPlan docs/test-grup-1.md` includes `TEST-LISTESI.md`, `manifest.json` (version, source commit, payload SHA-256) and writes a `.zip.sha256` sidecar. PowerShell 7 is enforced. Package sources under `CoopAndreas/`, `tunnel/`, `installer/`, `scripts/` and `docs/` must all be committed first. Local delivery logs and the previous installed mod/package are in `backups/group1-delivery-20261015/`. The current delivery is 0.3.103-alpha (remote player ped recovery, player state kept with the host's save) with the unchanged compiled Group 1 scripts; round 2 of the two-player test is pending.
- `backups/` (local only) — the Steam-era save files, kept untouched, and `CoopAndreas-upstream-clone.git` (the git dir of the original upstream clone from before the import; safe to delete).
- `dist/` (local only) — `CoopTunnel/` + `CoopTunnel.zip` come from `scripts/publish-tunnel.ps1`, `CoopAndreas-Kurulum/` + `.zip` from `scripts/package.ps1`.
- Game copy: `C:\Games\GTASA_Coop`, copied from Steam and downgraded on 2026-10-15 with the gtasa-open-downgrader v2 patches (applied with official xdelta3 3.1.0). `gta_sa.exe` = 1.0 US Hoodlum, MD5 `170b3a9108687b26da2d8901c6948a18`. The Steam install is the pristine backup.

## Reverse engineering (ReVa)
- ReVa (github.com/cyberkaida/reverse-engineering-assistant 7.3.1, Apache-2.0, a Ghidra MCP server) is registered for this checkout only, as a local-scope MCP server (`claude mcp get ReVa`; the registration lives in `~/.claude.json`, not in the repo; `claude mcp remove ReVa -s local` removes it). Claude Code starts `tools/ghidra/reva_persistent.py` with the Python of the ReVa uv tool (`uv tool install "reverse-engineering-assistant==7.3.1" --with "mcp<2"`; mcp 2.x breaks `mcp-reva`), which runs ReVa's headless server on the analyzed project in `.tools/ghidra-projects` instead of mcp-reva's throw-away project: stdio to Claude Code, HTTP only on 127.0.0.1 with a random API key per session, no outbound connections or telemetry. The Ghidra side is ReVa's release zip for Ghidra 12.1.3 (`.tools/reva/`, loaded with `-Dghidra.external.modules`, nothing installed into Ghidra); it runs on the local Ghidra 12.1.4 named in the registration (`GHIDRA_INSTALL_DIR`, JDK through `JAVA_HOME_OVERRIDE`). Start-up takes about 8 s, a decompile or cross-reference query 1–5 s, and the server holds about 2 GB of RAM while the session is open. Agents spawned from this session use the same server.
- The project: gta_sa.exe 1.0 US analyzed once (21,041 functions), then named from gta-reversed and plugin-sdk by `tools/ghidra/update-project.ps1` (`gta_names.py` writes `gta_sa_names.tsv`, `ApplyGtaNames.java` applies it and lists what it skipped in `gta_sa_names.tsv.report.txt`): 14,559 of 23,114 functions named, gta-reversed first. `<Name>_hoodlum` is a copy the Hoodlum exe relocated into its `.HOODLUM` section, `<Name>_body` the rest of a function behind a detour stub. No calling conventions or `this` types are set (the decompiler shows `in_ECX`).
- Rules: ReVa output explains code; a hook or patch site still cites plugin-sdk, gta-reversed or bytes read with `tools/pe_peek.py`. Treat the vtable tools' results as candidates (ReVa placed CPlayerPed's vtable at 0x86D158; it is 0x86D168). Constant search misses memory operands inside a range (e.g. `[0xA49963]`): query cross-references on the address or use dumpbin. Look functions up by address (qualified names aren't found). Keep knowledge in the repo pipeline (names in `gta_names.py`/`ApplyGtaNames.java`, notes in docs) rather than ReVa's `checkin-program`, which puts the program under Ghidra's version control and grows the project from about 110 MB to about 350 MB. `run-script` runs Python inside the server with the user's rights: only scripts written for the task, never code taken from analyzed content. `search-decompilation` needs `overrideMaxFunctionsLimit` on this program (over 1,000 functions); cross-references are usually the better tool. The names pipeline doesn't read plugin-sdk's `#define FUNC_<Class>__<Method>` addresses yet (e.g. `CMissionCleanup::Process` 0x468560 still shows as `FUN_00468560`).
- One process per project: `update-project.ps1` (or any `analyzeHeadless` on the project) needs every session with ReVa in this checkout closed, and a second concurrent ReVa session gets a temporary copy whose edits are lost. Ghidra refuses project paths with a folder that starts with '.', so the wrapper and the script open `.tools` paths by their 8.3 short name.

## Rules
- Never modify the Steam install (`C:\Program Files (x86)\Steam\steamapps\common\Grand Theft Auto San Andreas`); work only on `C:\Games\GTASA_Coop`.
- Everything targets the 1.0 US executable (`PLUGIN_SGV_10US`, hard-coded 1.0 US hook addresses); don't reverse-engineer the Steam `gta-sa.exe`.
- The user wants no ties to third parties: no CoopAndreas Discord or serial key, no telemetry. Keep it that way in new changes.
- Start the game with `gta_sa.exe --coop` (the `CoopAndreas` shortcut); the proxy `eax.dll` only loads the mod with `--coop`, so plain `gta_sa.exe` is vanilla single-player. The server is `server\server.exe` (config `server-config.ini` next to it, UDP port 6767).
- The client loads its own `CoopAndreas\main.scm` and `CoopAndreas\script.img`; the game's `data\script` stays vanilla. Don't let Sanny Builder's copy-to-game-directory overwrite it.
- GPL-3.0: when the friend gets our build, they get its source too.
- The repo is public: no game files, downgrade patches, saves, secrets or the friend's personal details in it.
- Never break the story mission order (the user's rule, 2026-10-15; otherwise the game can break). Missions are ported, tested and played in story order, and a port changes only the inside of its own mission: the order missions unlock in, their start triggers, and the progression and story flags in the MAIN section stay as in the original.
- Keep co-op saves loadable from one package to the next: the players continue their save across batches. A mission port changes mission code only; no new global variables and no changes to MAIN or to external scripts that run outside missions (saved script positions would land in garbage, as with the Steam saves). The SCM pipeline checks this before a package goes out.

- This session is the project's architect (the user's decision, 2026-10-15; they leave the decisions to it): it plans the work, writes work-package briefs, reviews and merges what comes back, builds, deploys to the game copy, packages for the friend, commits and pushes, keeps this file and `YAPILACAKLAR.md` current, and talks to the user in Turkish. It may code small things itself.
- Coding and checking go to Opus 5.5 subagents defined in `C:\Users\samet\.claude\agents\` (the user's pattern from their other projects; `memory: user`; the brief carries only the task; coders never commit):
  - `gtasa-coder` (effort medium): installer, scripts and tunnel changes, docs, client/server features that copy an existing pattern, mission ports that follow the porting guide.
  - `gtasa-coder-high` (effort high): new hooks and anything that needs 1.0 US addresses, packet changes across `shared/`, client and server, host/opcode sync, threading (ENet vs. the game loop), crash and hang investigations, and review-only briefs.
- New or changed agent definitions reach a running session only after a while (in wave 1 they showed up after the agents had been dispatched). Until the Agent tool accepts the type, dispatch `general-purpose` with model opus and the definition's rules pasted above the brief.
- Agents run in their own git worktrees (Agent `isolation: "worktree"`, under `.claude/worktrees/`) from a base commit on `main` named in the brief, so several can work at once; a fresh worktree builds everything in about 30 s. The architect merges them into `main` one at a time (commit in the worktree, cherry-pick onto `main`, remove the worktree and its branch), rebuilds after each and resolves overlaps (packet IDs, handler tables, hook registration).
- Only the architect deploys (`scripts/deploy.ps1`), packages (`scripts/package.ps1`, the tunnel publish to `dist/`) and touches git history. Nobody starts or stops `gta_sa.exe`, `server.exe` or `CoopTunnel.exe` unless the brief says so; the user may be playing with the friend.
- Mission batches are gated (the user's rule, 2026-10-15): when a batch is merged, the architect builds, deploys and packages it with a test list and waits; the next batch starts only after the user has tested and approved. Bug fixes and non-mission work may go on meanwhile. No mission is skipped: a batch stops at a blocked mission until the blocker is solved.
- Every new 1.0 US address, offset or calling convention cites its source (plugin-sdk, gta-reversed, or bytes read from `C:\Games\GTASA_Coop\gta_sa.exe` with `tools/pe_peek.py`); never a guess. A packet change updates `shared/`, client and server together and means the friend needs a new package.
- Gates: `scripts/build.ps1` for C++ (plus `tools/audit_hooks.py` when hook or patch sites change), `dotnet build -c Release` in `tunnel/`, a Windows PowerShell 5.1 parse of changed `.ps1` files (and `deploy.ps1 -WhatIf`), `scripts/compile-scm.ps1 -OutDir <scratch>` for missions (it enforces the size and save checks; runs are serialized). Only the user can test in game, two-player features with the friend; reports say what wasn't tested in game and give the test steps.
- Git: `core.autocrlf=true` (working tree CRLF, index LF). `origin` is the user's repo; never push anywhere else.

## Fork changes (keep them small for upstream merges)
Committed on top of the upstream import.
- `COOP_NO_SERIAL_CHECK` (defined in `xmake.lua`, used in `client/src/CLaunchManager.cpp`): no launcher serial check.
- `COOP_NO_DISCORD_RPC` (defined in `xmake.lua`, used in `client/src/CDiscordRPC.cpp` and `CDiscordRPCMgr.cpp`): no Discord Rich Presence. `Discord_Initialize` (named-pipe IPC to the Discord client, `discord-<appid>` URL handler written to HKCU) and the presence updates are compiled out, so no discord-rpc code is linked into the client; the `discordrpc` target still builds. The URL handler older builds left behind (`HKCU\Software\Classes\discord-1324128258672951317`) is removed, when present, by `deploy.ps1` (honours `-WhatIf`) and by `Kur.ps1` (fresh install and update).
- `COOP_NO_CRASH_UPLOAD` (defined in `xmake.lua`, used in `client/src/CCrashReporter.cpp` and `CHttp.cpp`): no crash report upload. The report server lookup (a GitHub gist read at start-up) and the HTTPS POST of the crash log are compiled out whatever `report-crashlogs` in `coopandreas.ini` says, and so is the WinHTTP client in `CHttp.cpp` (`winhttp.dll` isn't imported; a new `CHttp` caller fails to link). The local crash log (`CoopAndreas_crashes\*.log`), the dialog's Save Dump button and the crash dialog stay. The opt-in defaults stay as well: `report-crashlogs` is `false` in `client/src/CConfigLoader.h`, `CConfigLoader.cpp` and `CCrashReporter.h`.
- `IMGUI_DISABLE_DEFAULT_SHELL_FUNCTIONS` (defined in `xmake.lua` for the client, which compiles ImGui): ImGui's `TextLinkOpenURL` links (only in ImGui's own debug and error windows) open nothing, so ImGui has no `ShellExecute`.
- Server listen address: `bind` in `server\server-config.ini` (`server/src/ConfigManager.*`, used in `CNetwork::Init`), an IPv4 address; `0.0.0.0` (all interfaces, as upstream) by default and when the key is missing or empty. A value that isn't an IPv4 address makes `server.exe` print an error and exit instead of listening everywhere. Configs that this build creates get a `bind = 0.0.0.0` line; existing ones (the game copy's) don't have it. When playing over CoopTunnel, put `bind = 127.0.0.1` in `server-config.ini` and restart `server.exe`: the tunnel host forwards to 127.0.0.1:6767, the host's own game must connect to 127.0.0.1 too, and nothing on the LAN can reach the server.
- Story host pinning: `story-host` in `server\server-config.ini` (`server/src/ConfigManager.*`, rule in `CHostPolicy.h`, applied by `CHostManager.*`) names the player who is always the host, as the server sees nicknames (characters other than a-z, A-Z, 0-9, `_`, `[`, `]` become `_`, at most 24, case-sensitive). When set, nobody else becomes host: a player who connects first waits without one, and a story host who leaves isn't replaced until they are back. Empty or missing keeps upstream's rule (the first player in the list). Configs this build creates get an empty `story-host =` line; `deploy.ps1` fills a missing key. The server prints every decision (`[Host] : ...`). A player who connects while a host exists now gets `PLAYER_ASSIGN_HOST` too (upstream never told a joiner who the host was); there is no packet for "nobody": the games learn it from the host's `PLAYER_DISCONNECTED`. A leaving player is also taken out of every vehicle seat and its deleted peds out of every claim list (stale pointers could make a reconnected player's peer a vehicle's syncer). New host-only handlers relay with `CHostManager::SendFromHostToOthers` / `SendFromHostToPlayer`. No wire change.
- Session lifecycle (`client/src/CSessionLifecycle.*`, state in `CSessionPolicy.h`): one source of session events for the mirror layer, the world-state registry and later modules, on the game thread; modules `Subscribe` once instead of editing `PacketHandlers/system.cpp`. Events: AUTHENTICATED, DISCONNECTED, HOST_CHANGED (also to nobody), PLAYER_JOINED (host side, also for the players already in when this game becomes host), PLAYER_LEFT, GAME_RESTARTED (frame counter), SAVE_LOADED (the `GenericLoad` hook at 0x53C70B), HOST_MISSION_STARTED/ENDED (the host's `$onmission` edge in `Main.cpp`, `ON_MISSION_FLAG_SYNC` on the others). Helpers: `IsHost`, `HasHost`, `GetHostId`, `IsHostOnMission`, `IsLocalGameReady`, `IsInFreePlay`/`GetFreePlayDuration` (CPlayerStateSave's free-play rule, which now lives there), `IsLocalMissionRunning`. A game that becomes host with players in sends them the join snapshot (static blips, EnEx, tags, moon; the world state comes from the registry). When the host leaves during its mission (or the session ends then), the others clear their copy of it 250 ms later, after the host's buffered packets: its cutscene (02EA), camera (02EB, 0373), player control (01B4) and upstream's `ON_MISSION_FLAG_SYNC` 1→0 clean-up, unless a mission of their own runs. `--coopdiag`: events in `CoopAndreas_session.log`, a `session:` line in `CoopAndreas_diag.log`. Two-player test pending. A takeover's join snapshot and its PLAYER_JOINED events wait for this game's first server-time answer (`CServerTime::m_serverTimeOffset != 0`): a story host who connects second becomes the host in its handshake frame, and packets sent before the clock answer carry the PC's uptime as their stamp and wait in the others' packet buffers.
- Frame limiter always on (`CPatch::PatchFramerate`, byte patch at `0x748D68`). Upstream removes the 14 ms frame delay and relies on the menu's Frame Limiter; with it off the game runs at ~2000+ FPS, per-frame time rounds to 0 ms and New Game sits on a black screen.
- Startup resolution selection (`CPatch.cpp`, `PatchStreaming`): the Device Selection dialog's `FillAvailableVMs` at 0x745920 has a separate aspect filter from the in-game `GetVideoModeList` filter already patched at 0x745BC9. Original executable bytes at 0x7459E1 are `7A 71` (jump to 0x745A54); the startup whitelist excludes 16:9, including the user's driver-supported 2560x1440. Byte-check and NOP this two-byte rejection, accepting an already-NOPed site and logging/skipping an unexpected signature. Keep driver modes, selected adapter, fullscreen/minimum-size checks, depth options and raw mode IDs. No forced resolution or video-settings reset. Source: `.tools/gta-reversed/source/app/platform/win/VideoModeSelectDialog.cpp` plus actual 1.0 US bytes (the original binary's ratio whitelist differs from that reference). Local evidence: `backups/display-fix-20261015/`. Client-only UI fix keeps 0.3.102-alpha and the existing server protocol; package commit/hash distinguish this build. Actual dialog selection remains user-tested.
- `--coopdiag` (`client/src/Debug/CDiagLog.*`, started from `CCore::Init`): writes `CoopAndreas_diag.log` in the game folder every 2 s (frame counter, game time, pause/menu/fade, network, focus, script IPs). It keeps writing if the game loop hangs.
- Tag sync (`client/src/Hooks/WorldHooks.cpp`, `PacketHandlers/world.cpp`): the spray hook calls 0x565B70 with an `int` return (plugin-sdk's `bool` let the compiler drop the "tag reached 255" update), hits above alpha 228 (`CTagManager::ALPHA_TAGGED`) go out unthrottled, and remote tag updates never lower a tag. Fixes Tagging Up Turf not counting the other player's tags. Lesson: plugin-sdk return types can be wrong; check the exe when a hook compares a result against more than 0/1.
- Background keepalive (`client/src/CNetworkKeepAlive.*`): WinMain's background `Sleep(100)` (call at 0x748DC3, operand patched after a byte check) waits on the ENet socket instead, so alt-tab and minimize no longer time out. Reliable packets are kept and handled in the first frame back, unreliable sync snapshots and stale server-time answers are dropped; the game itself stays paused. `--coopdiag` shows `bgKept`/`bgDropped`.
- Radio sync (`client/src/CRadioSync.*`, packet `VEHICLE_RADIO_STATION`, server relay): passengers follow a network driver's station and their station keys do nothing (RedirectCall 0x4EB72A / 0x4EB753). Also fixes upstream's car-audio Service running in the remote player's focus (`VehicleHooks.cpp`), which switched the local radio on for the other player's car.
- Wanted level from the host's missions (`client/src/COpCodeSync.cpp` `syncedOpcodes[]`): in synced (ported) missions the host's alter wanted level (010D), alter wanted level no drop (010E), clear wanted level (0110), police ignore player (01F7), max wanted level (01F0), wanted multiplier (03C7) and disable military zones (0A24) run on every game; the PLAYER parameter is replayed as the local player. ## Known limitations
- Old saves can't be loaded: the co-op `main.scm` differs, so saved script IPs land in garbage (crash in e.g. `quarrys`). Always New Game.
- While a player is alt-tabbed their game is paused: the host's mission scripts wait, and the other player sees the away player's ped and the peds the host syncs frozen (a held key keeps replaying until they return). The connection itself stays up.

## Missions
Mission sources are `CoopAndreas/scm/scripts/*.txt` (decompiled SA scripts plus co-op commands), included from `scm/main.txt`. Compile them with `scripts/compile-scm.ps1` (`-OutDir <folder>` for a scratch build; ~10 s): it runs Sanny Builder 4's CLI (`sanny.exe --no-splash --mode sa_sbl_coopandreas -o … --compile <main.txt> <out\main.scm>`) on an invisible desktop of its own, reads the IDE files of `C:\Games\GTASA_Coop` and never writes there, and writes `scm/main.scm` + `script.img` only when Sanny Builder logged nothing to `compile.log` (its CLI exits 0 and writes output even on errors), the scripts fit the 1.0 script space (MAIN 200,000 bytes, a mission 69,000) and saves stay loadable (globals, header, external script list and MAIN code unchanged against HEAD's `main.scm` or `-CompareTo`; `-SkipSaveCheck` only for a decided save break). Recompiling the unchanged sources reproduces the committed files except the compiler signature and string padding bytes the game never reads. `deploy.ps1` installs the committed `scm/main.scm` + `script.img`. Porting guide: `docs/mission-porting.md`; every story mission with status, risks, sizes and the porting order: `docs/missions.md`.
